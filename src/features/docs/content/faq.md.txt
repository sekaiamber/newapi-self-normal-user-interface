出错时，先看响应 JSON 里 `error.message` 给出的原因，再对照下面的条目排查。需要联系管理员时，请附上请求时间、模型名、密钥名称（不要发送密钥本身），以及调用记录详情中的请求 ID。

## 密钥无效、未授权或禁止访问

常见表现：返回未授权（HTTP 401）或禁止访问（HTTP 403）。逐项检查：

1. **认证头格式**：应为 `Authorization: Bearer sk-...`，`Bearer` 与密钥之间有一个空格；复制的密钥要完整，包括 `sk-` 前缀。
2. **密钥状态**：在「API 密钥」页面确认密钥处于启用状态、没有过期、没有被删除。删除后的密钥会立即失效，只能重新创建。
3. **IP 白名单**：设置了白名单时，只有名单内的来源 IP 可以调用。换了网络或通过代理访问时，出口 IP 可能已经变化。
4. **接口地址**：OpenAI 兼容客户端用 `{{BASE_URL}}/v1`，不要漏掉或重复 `/v1`。
5. **原生格式的写法**：Claude 接口用 `x-api-key` 时必须同时带 `anthropic-version` 请求头；Gemini 接口的密钥放在 URL 参数 `key` 中。

快速自检：下面的命令能返回模型列表，说明密钥和地址都没问题。

```bash
curl "{{BASE_URL}}/v1/models" \
  -H "Authorization: Bearer sk-替换为你的密钥"
```

## 提示额度不足

账户余额和密钥额度是两层独立的限制，任何一层不够都会失败：

- **密钥额度用完**：账户余额充足却提示额度不足，多半是这种情况。在「API 密钥」页面编辑该密钥，调高额度，或关闭「设置额度上限」改为不限额。
- **账户余额不足**：在「钱包」页面查看当前余额，按本站开放的方式在线充值或输入兑换码；没有可用的充值方式时，请联系管理员。
- **订阅额度不足**：如果你购买了订阅套餐，扣费顺序由「钱包」页的计费偏好决定。选择「仅用订阅」或「仅用钱包」时，对应的一方不足就会直接失败，不会改用另一方。

可以在「个人资料」的「通知」卡片里设置「余额低于多少时提醒」（与余额同一单位），余额低于该值时提前收到提醒。详见 [API 密钥与额度](/docs/tokens-and-quota)。

## 模型不存在或没有可用渠道

常见表现：提示模型不存在（`model_not_found`），或提示没有可用渠道。

1. **核对模型名**：模型名必须和模型列表中的 `id` 完全一致，包括大小写和版本后缀。可以单独查询某个模型：

```bash
curl "{{BASE_URL}}/v1/models/gpt-4o-mini" \
  -H "Authorization: Bearer sk-替换为你的密钥"
```

2. **检查密钥的模型限制**：如果给密钥设置了「模型限制」，只能调用列表中勾选的模型。
3. **检查密钥的分组**：分组决定能使用哪些渠道。同一个模型可能只在某些分组下提供，可以换一个分组，或改用 `auto` 分组让系统自动挑选。
4. 以上都没问题仍然提示没有可用渠道，说明本站暂时没有为你的分组配置该模型的渠道，请联系管理员。

## 请求过于频繁（429）

接口文档将 HTTP `429` 列为请求频率受限。可能的来源：

- **本站的频率限制**：管理员可以按来源 IP 设置全局请求频率上限，也可以按分组限制每分钟、每小时的请求数。
- **上游渠道限流**：提示「当前分组负载已饱和，请稍后再试」时，表示上游渠道返回了 429（请求过多）。

处理建议：

- 降低并发，失败后等待一段时间再重试，并逐次拉长等待时间（指数退避）；
- 使用 `auto` 分组并开启「跨分组重试」，当前分组的渠道失败时会按顺序尝试下一个分组；
- 长期频繁触发时，请联系管理员确认你所在分组的限额。

## 流式输出异常

- **没有逐字输出**：确认请求体里有 `"stream": true`；Gemini 需要使用 `streamGenerateContent` 并加 `alt=sse` 参数。用 curl 测试时加 `-N` 关闭缓冲，示例见 [API 基础](/docs/api-basics#流式输出)。
- **长时间生成后中断或回复为空**：服务器对单次流式响应设有超时时间，超过后连接会被中断，可能表现为空回复。如果你的任务确实需要很长时间才有输出，请联系管理员确认超时设置。
- **网页应用里流式请求失败**：HTTPS 页面不能请求 HTTP 地址，请使用 `{{BASE_URL}}` 这样的 HTTPS 地址。
- **确认是否真的走了流式**：在「调用记录」的详情里可以看到调用方式（流式 / 非流式），流式请求还可能显示首字时间。

## 调用记录里找不到某次请求

- 日志支持按时间、模型、分组、API 密钥名称和请求 ID 筛选，先确认筛选条件没有排除这条记录。
- 是否记录消耗日志、哪些错误会写入错误日志，由管理员的设置决定，因此并不是每一次失败都会留下记录。
